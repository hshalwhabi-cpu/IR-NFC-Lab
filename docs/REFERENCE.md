# المرجع التقني الكامل — IR و NFC على أندرويد

هذا المستند يشرح كل واجهة برمجية استُخدمت، وحدودها، ولماذا اختيرت. مقسّم لقسمين.

---

# القسم الأول: الأشعة تحت الحمراء (IR)

## 1. الواجهة الوحيدة الرسمية: `ConsumerIrManager`

منذ أندرويد 4.4 (API 19) توفّر المنظومة صنفًا واحدًا للتعامل مع باعث IR:

```kotlin
val cir = context.getSystemService(Context.CONSUMER_IR_SERVICE) as ConsumerIrManager
cir.hasIrEmitter()            // هل يوجد باعث؟
cir.carrierFrequencies        // نطاقات التردد المدعومة
cir.transmit(carrierHz, pattern)  // الإرسال
```

- **`transmit(int carrierFrequency, int[] pattern)`**: `pattern` مصفوفة مدد بالميكروثانية
  بالتناوب: [تشغيل، إطفاء، تشغيل، إطفاء ...]. الفهرس 0 = أول نبضة حامل (mark).
- `carrierFrequency` بالهرتز (شائع: 38000 لمعظم الأجهزة، 36000 لفيليبس، 40000 لسوني).

### الحدود الحرجة
| القدرة | متاح؟ | كيف |
|--------|-------|-----|
| إرسال IR | ✅ نعم | `ConsumerIrManager.transmit()` |
| معرفة الترددات | ✅ نعم | `carrierFrequencies` |
| **قراءة/التقاط IR** | ❌ **لا يوجد API عام** | يتطلب root + مستقبل عتادي |

> **لماذا لا توجد قراءة؟** لأن معظم هواتف IR (ومنها Note 600 Pro غالبًا) تحتوي
> على **باعث LED فقط** بلا مستقبل. وحتى لو وُجد مستقبل، فأندرويد لا يعرّض واجهة
> عامة له. الوصول المنخفض يكون عبر `/dev/lirc*` أو `/sys/class/rc/` وكلها تتطلب
> صلاحيات root. التطبيق يفحص هذه المسارات ويخبرك بالنتيجة.

## 2. البدائل العملية للقراءة (المطبّقة في التطبيق)
1. **استيراد Pronto/RAW**: قواعد بيانات ضخمة للريموتات متاحة مجانًا (مثل قاعدة LIRC،
   وملفات Flipper IRDB). تلصق الكود وتُرسله فورًا.
2. **المسح التلقائي (Brute-force)**: يرسل كل أوامر بروتوكول ضمن نطاق (مثلًا 0x00→0xFF)
   بفاصل زمني، وتراقب متى يستجيب الجهاز. أسرع طريقة لاكتشاف كود مجهول بلا قارئ.
3. **قارئ خارجي**: ESP32/Arduino + مستقبل TSOP4838 يلتقط التوقيتات، وتلصقها في
   تبويب «النمط الخام».

## 3. البروتوكولات المطبّقة وتوقيتاتها

### NEC (الأشهر — تلفزيونات، مكيّفات، أجهزة استقبال)
- الحامل 38 kHz. رأس: mark 9000µs + space 4500µs.
- بت 0 = mark 560 + space 560. بت 1 = mark 560 + space 1690. نهاية = mark 560.
- الإطار 32-bit: عنوان + معكوس العنوان + أمر + معكوس الأمر (للتحقق من الأخطاء).
- إطار تكرار خاص عند الضغط المستمر: mark 9000 + space 2250 + mark 560.

### Samsung
- مثل NEC لكن الرأس mark 4500 + space 4500، والإطار عنوان+عنوان+أمر+معكوس.

### Sony SIRC (12/15/20 بت)
- الحامل 40 kHz. ترميز عرض النبضة: بت 0 = mark 600، بت 1 = mark 1200، الفاصل 600.
- رأس mark 2400 + space 600. يُرسل الأمر أولًا (7 بت) ثم العنوان. الدورة 45ms.
- **يجب تكراره 3 مرات** ليُقبل عادةً.

### Philips RC5 / RC6
- الحامل 36 kHz. ترميز مانشستر (RC5) أو مانشستر معدّل (RC6).
- **بت التبديل (Toggle)**: ينقلب مع كل ضغطة جديدة ليميّز «ضغطتين» عن «ضغطة مستمرة».
  لهذا التطبيق يوفّر خانة Toggle.

### JVC / Kaseikyo (Panasonic)
- JVC: رأس 8400/4200، لا يكرر الرأس عند التكرار.
- Kaseikyo: إطار 48-bit، الحامل 37 kHz.

## 4. صيغة Pronto HEX (CCF)
أشهر صيغة لمشاركة أكواد الريموتات:
```
0000 <معامل التردد> <أزواج المقدمة> <أزواج التكرار> <أزواج القيم...>
```
- `0000` = صيغة خام معدّلة (مدعومة). `0100` = صيغة أخرى (مدعومة أيضًا).
- التردد = 1,000,000 / (معامل التردد × 0.241246) هرتز.
- كل قيمة = عدد دورات الحامل، تُضرب في مدة الدورة للحصول على الميكروثانية.

# القسم الثاني: NFC

على عكس IR، تقنية NFC **مفتوحة بالكامل** لتطبيقات أندرويد بلا root.

## 1. اكتشاف التاق: Foreground Dispatch
```kotlin
adapter.enableForegroundDispatch(activity, pendingIntent, null, null)
// عند اللمس يصل Intent فيه:
val tag = intent.getParcelableExtra(NfcAdapter.EXTRA_TAG, Tag::class.java)
```
هذا يضمن أن تطبيقك يلتقط كل التاقات ما دام مفتوحًا (بأولوية على غيره).

## 2. طبقات التقنية (Tag Technologies)
`Tag.getTechList()` يخبرك بما تدعمه البطاقة. الأصناف:

| الصنف | المعيار | ماذا يقرأ |
|-------|---------|-----------|
| `NfcA` | ISO 14443-3A | ATQA, SAK, transceive خام |
| `NfcB` | ISO 14443-3B | بيانات التطبيق والبروتوكول |
| `NfcF` | JIS FeliCa | رمز النظام (ياباني — مواصلات) |
| `NfcV` | ISO 15693 | بطاقات بعيدة المدى |
| `IsoDep` | ISO 14443-4 | أوامر APDU (بنوك، هوية، جوازات) |
| `MifareClassic` | خاص NXP | قطاعات وكتل بمصادقة مفاتيح |
| `MifareUltralight` | خاص NXP | صفحات 4 بايت |
| `Ndef` | NFC Forum | رسائل NDEF منظّمة |
| `NdefFormatable` | — | تاق فارغ قابل للتنسيق |

## 3. القراءة الكاملة (بلا root)
- **UID**: `tag.getId()` — دائمًا متاح.
- **MIFARE Classic**: التطبيق يجرّب مفاتيح شائعة (FFFFFF...، A0A1A2...، مفاتيح NDEF)
  لكل قطاع، ويقرأ كل كتلة نجحت مصادقتها. البطاقات المشفّرة بمفاتيح مخصصة لن تُقرأ.
- **Ultralight**: يقرأ كل الصفحات عبر `readPages()` (تُرجع 16 بايت كل مرة).
- **NDEF**: `ndef.cachedNdefMessage` ثم تفكيك السجلات (نص، رابط، MIME...).

## 4. الكتابة (NDEF)
```kotlin
val record = NdefRecord.createUri("https://...")
val msg = NdefMessage(arrayOf(record))
Ndef.get(tag).apply { connect(); writeNdefMessage(msg); close() }
```
- أنواع السجلات: نص (`RTD_TEXT`)، رابط (`createUri`)، MIME (`createMime`)،
  تشغيل تطبيق (`createApplicationRecord`)، خارجي (`createExternal`).
- **القفل النهائي**: `ndef.makeReadOnly()` — **لا رجعة فيه إطلاقًا**، يجعل التاق للقراءة فقط.
- تنسيق تاق فارغ: `NdefFormatable.get(tag).format(msg)`.

## 5. أوامر APDU الخام (IsoDep)
لأغراض متقدمة: بطاقات البنوك، الهوية، المواصلات.
```kotlin
val iso = IsoDep.get(tag); iso.connect()
val response = iso.transceive(hexToBytes("00A4040007D276000085010100"))
// آخر بايتين = Status Word: 9000 نجاح، 6A82 غير موجود...
```
أوامر جاهزة في التطبيق: SELECT PPSE (كشف بطاقات Visa/MC)، SELECT NDEF App،
READ BINARY، GET DATA (UID)، GET CPLC.

> ⚠️ بطاقات الدفع مشفّرة ومحمية؛ يمكنك رؤية بنيتها (AID، التطبيقات) لكن ليس
> بيانات حساسة كرقم PIN أو المفاتيح.

## 6. محاكاة البطاقة (HCE — Host Card Emulation)
يحوّل جوالك إلى **بطاقة** يقرأها جهاز NFC آخر، بلا عنصر أمان (Secure Element).
- خدمة ترث `HostApduService` وتُسجَّل في المانيفست مع ملف `apduservice.xml` يحدد
  الـ **AID** (معرّف التطبيق) الذي تستجيب له.
- التطبيق يطبّق **تطبيق NDEF Type-4 كامل**: يستجيب لـ SELECT الخاص بـ NDEF
  (`D2760000850101`)، ويقدّم Capability Container وملف NDEF — فيظهر جوالك لأي قارئ
  كأنه تاق NDEF حقيقي يحمل نصًا تحدّده أنت.
- بالإضافة إلى **AID مخصص** (`F0524151492D4C4142`) يردّ بردّ HEX تتحكم به من الواجهة —
  مفيد لتجربة قارئات NFC وبناء بروتوكولاتك.

### حدود HCE
- لا يمكن محاكاة **UID ثابت** (النظام يولّد UID عشوائيًا لكل جلسة — قيد أمني في أندرويد).
- لا يمكن محاكاة MIFARE Classic (يحتاج عتادًا خاصًا غير موجود في معظم الأجهزة).
- محاكاة بطاقات الدفع تتطلب اتفاقيات مع الشبكات ومفاتيح لا تُمنح لتطبيقات عادية.

## جدول ملخّص: ما الممكن على Note 600 Pro؟

| المهمة | بدون root | ملاحظة |
|--------|:--------:|--------|
| إرسال IR بأي بروتوكول | ✅ | عبر ConsumerIrManager |
| قراءة/التقاط IR | ❌ | لا API؛ استخدم المسح أو قارئًا خارجيًا |
| قراءة تاقات NFC كاملة | ✅ | حتى MIFARE بمفاتيح معروفة |
| كتابة NDEF + قفل | ✅ | — |
| APDU خام (IsoDep) | ✅ | لا يكشف أسرارًا مشفّرة |
| محاكاة تاق NDEF (HCE) | ✅ | UID عشوائي فقط |
| محاكاة MIFARE Classic | ❌ | قيد عتادي |
